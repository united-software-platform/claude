# usp-claude

Окружение для изолированного запуска Claude Code в Docker-контейнере: агент работает только внутри
каталога проекта, под отдельным аккаунтом и с отдельным SSH-ключом. Окружение не привязано к языку
и стеку проекта — набор файлов копируется в корень любого репозитория.

## Зачем

- **Изоляция файловой системы.** В контейнер монтируется только рабочее дерево проекта. Домашний каталог
  хоста, соседние репозитории и системные настройки агенту недоступны.
- **Несколько аккаунтов без перелогина.** Каждый профиль хранит авторизацию и конфиг в своём каталоге
  `.claude-accounts/<профиль>`. Личный и рабочий аккаунты живут параллельно, переключение — параметром запуска.
- **Отдельный SSH-ключ на проект.** Ключ и `known_hosts` лежат в `.ssh/` проекта и монтируются в контейнер;
  ключи хоста не задействованы.
- **Файлы остаются вашими.** Контейнерный пользователь `claude` создаётся с UID/GID хоста, поэтому созданные
  агентом файлы не оказываются во владении `root`.

## Требования

Docker с плагином `docker compose`, `make`, `ssh-keygen`.

## Быстрый старт

```bash
cp .env.example .env          # при необходимости поправьте IMAGE и SSH_COMMENT
make ssh-key                  # создаст .ssh/id_ed25519 и .ssh/config, выведет публичный ключ
make ssh-pub                  # публичный ключ — добавьте его в GitHub/GitLab
mkdir -p .claude-accounts/work
make rebuild                  # сборка образа
make claude CLAUDE_PROFILE=work
```

Первый запуск попросит авторизоваться — авторизация сохранится в `.claude-accounts/work` и переживёт
перезапуски контейнера.

> **Примечание:** `make ssh-key` берёт хост для `.ssh/config` из `git remote get-url origin`. Если remote
> ещё не настроен, config не создаётся — задайте `GIT_HOST` в `.env` или добавьте remote и повторите вызов.

## Команды

| Команда | Что делает |
|---------|------------|
| `make claude CLAUDE_PROFILE=<профиль>` | запустить Claude Code под выбранным аккаунтом |
| `make claude-shell CLAUDE_PROFILE=<профиль>` | войти в `bash` контейнера — авторизация `gh`, отладка, ручные команды |
| `make rebuild` | собрать образ; единственное место сборки |
| `make ssh-key` / `make ssh-pub` | создать ключ проекта / показать публичный ключ |
| `make up` / `make down` / `make restart` | поднять, остановить, пересоздать остальные сервисы окружения |
| `make help` | список команд и переменных |

`CLAUDE_PROFILE` обязателен: без него compose не соберёт путь к каталогу аккаунта и остановится с ошибкой.

Образ не пересобирается автоматически (`pull_policy: never`): после правки `docker/claude/Dockerfile`
нужен явный `make rebuild`.

## Короткие алиасы

Вместо `make` можно подключить shell-функции:

```bash
source .bashrc
claude-profile-add personal   # создать каталог профиля
claude-docker personal        # запустить Claude Code (по умолчанию профиль work)
claude-shell personal         # shell в контейнере
```

Для каждого существующего каталога в `.claude-accounts/` регистрируются алиасы `claude-<профиль>`
и `claude-shell-<профиль>`. Файл `.bashrc` сам читает `.env` и проверяет обязательные переменные.

## Подключение к своему проекту

Скопируйте в корень репозитория: `Makefile`, `docker-compose.yml`, `docker/`, `.bashrc`, `.env.example`
и релевантные строки `.gitignore`. Дальше — [Быстрый старт](#быстрый-старт).

Тег образа задаётся в `.env` переменной `IMAGE` и должен быть свой у каждого проекта, иначе проекты будут
перетирать образ друг друга. Значение по умолчанию для `PROJECT_PREFIX` в `Makefile` выводится из имени каталога.

> **Важно:** каталоги `.claude-accounts/`, `.ssh/` и файл `.env` содержат секреты и перечислены
> в `.gitignore` — в репозиторий они попадать не должны.

## Переменные окружения

Задаются в `.env` (образец — `.env.example`), читаются `Makefile`, `docker-compose.yml` и `.bashrc`.

| Переменная | Назначение |
|------------|------------|
| `IMAGE` | тег локального образа проекта |
| `PROJECT_DIR` | каталог проекта внутри контейнера |
| `CLAUDE_ACCOUNTS_DIR` | каталог с профилями аккаунтов на хосте |
| `CLAUDE_CONFIG_DIR` | путь конфига Claude внутри контейнера |
| `SSH_DIR` / `CONTAINER_SSH_DIR` | каталог ключей на хосте / в контейнере |
| `SSH_KEY`, `SSH_CONFIG`, `SSH_KNOWN_HOSTS` | файлы, создаваемые целью `ssh-key` |
| `SSH_COMMENT` | комментарий в генерируемом ключе |
| `GIT_HOST`, `GIT_USER` | хост и пользователь для `.ssh/config` |
| `USER_ID`, `GROUP_ID` | UID/GID пользователя `claude` в образе |

`CLAUDE_PROFILE` в `.env` не задаётся — он передаётся при запуске.

## Состав образа

Базовый образ `node:22-slim`, глобально установлен пакет `@anthropic-ai/claude-code`. Дополнительно:
`git`, `openssh-client`, `gh`, архиваторы (`zip`, `unzip`, `p7zip`, `tar`, `gzip`, `bzip2`, `xz`).

## Ограничения

- Инструменты конкретного языка проекта в образ не входят — их добавляют в `docker/claude/Dockerfile`
  под задачи проекта.
- Сервис `claude` вынесен в compose-профиль `claude`, поэтому `make up` его не поднимает: цель предназначена
  для сервисов окружения (база, брокер, вспомогательные контейнеры), добавляемых в `docker-compose.yml`.
  В текущем составе других сервисов нет.
- Файл `.env` обязателен: он подключён через `env_file`, а `IMAGE` и `CLAUDE_PROFILE` не имеют значений
  по умолчанию — при их отсутствии compose завершается с ошибкой.
